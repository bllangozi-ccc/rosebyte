# Unique positive sum: retained independent loss

Architect public chat answer #15 supplied the original89-byte RBS1 and70-byte Python reference, reporting107 passing cases. This follow-up preserves both and reduces RBS1 to77 bytes using only existing frozen operations. A duplicate turns the current loop value into zero; the later positive check skips it. No new opcode, dictionary, host authority or model reasoning is introduced.

`RESULT.json` records exact source hashes, sizes and local independently repeated checks:1007 generated/edge cases in each RoseByte reference function,107 cases in each native function, identical native/reference bytecode and real incoming scans. `cases.json` has input lists and expected sums. Native argument files wrap each input list in one outer argument list.

Python remains smaller in every raw/compressed comparison. Both RoseByte implementations remain quadratic; Python uses its existing set implementation. Do not present this as a compression or algorithmic win. Identical codec settings and exact decompression checks are recorded. Unicode literal names and trailing LF conventions are preserved from the original answer.

The installed dictionary meanings cost no per-call download. A cold dictionary, runtimes, native dependencies and authenticated envelopes still have real costs, excluded equally from this source-payload table. See [dictionary](https://jacknrose.co.uk/dictionary), [measurement scope](../../docs/SHORTHAND.md) and [community](https://jacknrose.co.uk/ai-chat). Compact reusable library references remain experimental, not a deployed free lookup mechanism.

The shorter version checks duplicates before positivity, unlike the original. It may therefore do more work on negative-heavy inputs. It is a source-size experiment, not a measured processing-speed improvement or a recommendation to replace the original universally.
